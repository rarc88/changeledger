## Request

Los equipos reportan que los agentes a veces no consiguen seguir el flujo. Los
datos muestran que fallan sobre todo donde el formato es manual: sufijos de
tareas del Plan, timestamps y marcadores. Se pide que el CLI repare lo
mecánicamente reparable en lugar de solo diagnosticarlo, reduciendo los ciclos
de corrección manual.

## Investigation

- En este repo hay commits dedicados a arreglar formato a mano
  (`docs(changeledger): fix Plan task timestamp format for #...`) y un retry de
  review causado por em dashes en descripciones históricas de tareas
  (20260616-151221).
- El propio contrato documenta un footgun: `(CRn) — verify: ...` es
  silenciosamente inválido (el parser descarta el verify y la tarea pierde su
  verificación). Si el contrato necesita advertir un error de sintaxis, la
  herramienta debería repararlo.
- `changeledger check` ya detecta estos defectos pero la reparación es edición
  manual, que los agentes ejecutan de memoria y con errores, especialmente tras
  compactaciones.
- Restricción: el parser debe seguir siendo estricto — una sola forma válida —
  para que los documentos no deriven en dialectos.

## Proposal

Comando `changeledger fix [id] [--dry-run]`:

- Repara solo defectos mecánicos e inequívocos: `(CRn) — verify: X` se
  reordena a `; verify: X (CRn)`; sufijos de resolución con guion simple en vez
  de em dash; timestamps casi-ISO normalizables; marcadores `[ x ]`/`[X]`
  normalizados a `[x]`.
- Sin `id` opera sobre todo el repo. `--dry-run` imprime el diff propuesto sin
  escribir. La operación es idempotente.
- Los defectos que exigen juicio (CR desconocido, tarea sin criterio) se listan
  bajo `requires manual fix` y nunca se tocan.
- `changeledger check` añade el hint `run: changeledger fix <id>` cuando algún
  defecto reportado es auto-reparable.

Alternativas descartadas:

- Parser tolerante que acepte ambas formas: crea dos sintaxis válidas y deriva
  del formato canónico; la reparación explícita mantiene una sola verdad.
- Seguir documentando los footguns en el contrato: es el statu quo y la
  evidencia muestra que no evita los errores.

## Specification

### CR1 — Reordenar verify mal colocado
- **Given** un Plan con la tarea `- [ ] Update src/foo.mjs (CR1) — verify: pnpm test`
- **When** se ejecuta `changeledger fix <id>`
- **Then** la línea queda `- [ ] Update src/foo.mjs; verify: pnpm test (CR1)`
- **And** `changeledger check <id>` deja de reportar ese defecto

### CR2 — Dry run sin efectos
- **Given** el mismo documento defectuoso
- **When** se ejecuta `changeledger fix <id> --dry-run`
- **Then** imprime el diff propuesto y el archivo en disco no cambia

### CR3 — Idempotencia
- **Given** un documento ya reparado
- **When** se ejecuta `changeledger fix <id>` de nuevo
- **Then** imprime `nothing to fix`, no modifica el archivo y termina con exit 0

### CR4 — Defectos manuales intactos
- **Given** una tarea que referencia el criterio inexistente `(CR9)`
- **When** se ejecuta `changeledger fix <id>`
- **Then** la línea no se modifica
- **And** se lista bajo `requires manual fix`

### CR5 — Hint desde check
- **Given** un documento con un defecto auto-reparable
- **When** se ejecuta `changeledger check <id>`
- **Then** el diagnóstico incluye `run: changeledger fix <id>`
