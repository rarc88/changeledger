## Request

Los agentes empiezan a trabajar sin consultar los changes y specs existentes,
aunque haya información directamente relacionada. El humano propone un comando
de búsqueda que los agentes puedan usar antes de investigar. Hoy el único
descubrimiento disponible es `list --status/--type` y `show <id>`: no existe
búsqueda por contenido.

## Investigation

- Más del 60% de los 169 changes de este repo no tienen ninguna referencia
  cruzada (ni `depends_on`, ni specs, ni menciones a otros changes); en
  `ionic-app` y `backend-laravel` existen familias densas de trabajo
  relacionado que los agentes redescubren cada vez.
- Cada repo acumula ~13 specs graduadas (verdad persistente) que casi nadie
  referencia: en `backend-laravel` solo 2/97 changes citan un spec.
- El corpus es pequeño (decenas a pocos cientos de documentos Markdown): un
  escaneo directo con ranking en memoria es suficiente; no hace falta índice
  persistente.
- Restricción del INTENT: el core es determinista, local-first y sin
  dependencias de AI o nube. "Búsqueda semántica" con embeddings queda fuera
  del core; puede ser una integración opcional futura si el uso lo justifica.
  Un ranking léxico cubre el caso real observado: los agentes buscan términos
  de dominio ("wallet", "app check", "reverb").

## Proposal

Comando `changeledger search <query...>` léxico y determinista:

- Corpus: todos los changes (incluidos archivados) y todas las specs del repo.
- Ranking: frecuencia de términos normalizados (minúsculas, sin acentos) con
  boosts fijos: título ×3, headings y CRs ×2, cuerpo ×1. Empates se ordenan por
  id descendente para que la salida sea estable.
- Salida por hit: `#<id> <status> <type> — <title>` (o `spec:<slug> — <title>`)
  más un snippet de la primera coincidencia. Opciones: `--limit` (default 10),
  `--type`, `--status`, `--json`.
- Contrato: `templates/contract/spec.md` añade el mandato de ejecutar
  `changeledger search` con los términos del request antes de escribir
  Investigation, y de registrar lo relevante (`depends_on` o mención).

Alternativas descartadas:

- Embeddings/semántica en el core: viola el INTENT (dependencias de AI/nube,
  no determinista); se reevalúa como integración opcional con datos de uso.
- Grep manual: ya es posible y no ocurre; sin ranking ni conciencia de
  frontmatter/stages no compite con el coste de leer 169 archivos.
- Índice persistente: estado que puede desincronizarse; innecesario a esta
  escala.

## Specification

### CR1 — Ranking con boost de título
- **Given** un change cuyo título contiene "wallet" y otro que solo contiene "wallet" en el cuerpo
- **When** se ejecuta `changeledger search wallet`
- **Then** ambos aparecen y el del título aparece primero
- **And** cada hit muestra `#<id> <status> <type> — <title>` y un snippet con la coincidencia

### CR2 — Filtros de tipo y estado
- **Given** hits de tipos `bug` y `feature` para el término "wallet"
- **When** se ejecuta `changeledger search wallet --type bug --status done`
- **Then** solo aparecen changes `bug` con estado `done`

### CR3 — Specs incluidas y distinguidas
- **Given** una spec `specs/wallet.md` que contiene el término buscado
- **When** se ejecuta `changeledger search wallet`
- **Then** aparece identificada como `spec:wallet` junto a los changes

### CR4 — Salida JSON estable
- **Given** cualquier búsqueda con hits
- **When** se añade `--json`
- **Then** imprime un array de objetos `{ref, title, score, snippet}` parseable y en el mismo orden que la salida de texto

### CR5 — Sin resultados
- **Given** un término sin coincidencias
- **When** se ejecuta `changeledger search zzzz`
- **Then** imprime `no matches` y termina con exit 0

### CR6 — Determinismo
- **Given** el mismo repo sin cambios
- **When** se ejecuta dos veces la misma búsqueda
- **Then** las dos salidas son byte a byte idénticas

### CR7 — Mandato en el contrato de autoría
- **Given** el contexto de autoría
- **When** se ejecuta `changeledger context spec`
- **Then** incluye la instrucción de buscar con `changeledger search` antes de escribir Investigation y registrar lo relevante
